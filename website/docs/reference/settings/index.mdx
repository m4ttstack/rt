# rt settings

`rt › settings`

Configure tokens, team, and repo data

## Usage

```bash
rt settings
```

## Subcommands

| Command | Description |
| --- | --- |
| [`get`](get) | Read a resolved setting (value + provenance) through the settings resolver |
| [`set`](set) | Write a setting into one authored store (user/team/machine) |
| [`unset`](unset) | Remove a setting from one authored store (the only supported way; hand-editing a store is not) |
| [`list`](list) | List every registered setting resolved through the settings resolver |
| [`explain`](explain) | Show the full scope chain for one setting, weakest first |
| [`check`](check) | Check every stored settings value against its schema and list unregistered keys |
| [`migrate`](migrate) | Carry stored settings to each key's current store name; a dry run unless --write or --prune |
| [`linear`](linear) | Linear API configuration |
| [`gitlab`](gitlab) | GitLab API configuration |
| [`notifications`](notifications) | Toggle notification preferences |
| [`test-push`](test-push) | Send a test push notification via rt tray |
| [`runaway`](runaway) | Configure runaway process detection thresholds |
| [`extension`](extension) | Install RT Context extension in editors |
| [`source-path`](source-path) | Show or set the rt source checkout the dev app runs |
| [`schema`](schema) | The settings schema lock: regenerate it from the registry, or diff the registry against a committed lock |
