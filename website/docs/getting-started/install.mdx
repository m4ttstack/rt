# Install

```bash
brew install m4ttheweric/tap/rt
rt setup status             # confirms the tray app, daemon, and integrations are healthy
```

`rt setup status` and [`rt verify`](/reference/verify) both health-check the tray app, daemon, editor extensions, and shell integration so you can confirm the install is in good shape. Run `rt setup plan` beforehand to see the readiness checklist for what Install still needs from you.

Then configure your API tokens:

```bash
rt settings linear token   # Linear API key (for ticket lookup)
rt settings gitlab token   # GitLab PAT (for MR status)
```

See [rt settings linear token](/reference/settings/linear/token) and [rt settings gitlab token](/reference/settings/gitlab/token) for details.

For detailed diagnostics at any time:

```bash
rt verify
```

## Repo folder

The setup checklist asks where rt should clone your team's repos instead of assuming a default location. You can also set this from the CLI for scripted installs:

```bash
rt setup repo-root set ~/code     # set the repo folder
```

Before Install (when the home repo doesn't exist yet), the answer is staged. After Install, it writes directly to the settings store. The tray app shows an OS folder picker for this step.

## Agent permissions

Install seeds a baseline `permissions.allow` list into Claude Code's settings so agents don't stall on per-tool prompts for calls rt already trusts. The seeded entries cover `glab` commands, the Fast Browser plugin, `EnterWorktree`, the mattstack MCP server, `rt skills sync`, `rt runs`, and `rt gate`. Existing entries are preserved; only missing ones are appended.

When a Claude config dir sets no `permissions.defaultMode`, Install seeds `auto`. Claude Code starts in auto mode by itself only on some plans; Enterprise and Console-key sessions otherwise start in manual mode and prompt for routine git. A mode you already chose is left alone.

## Plugins

Install adds rt's Claude Code plugins (`mattstack`, `fast-browser`, and `chat` from the mattstack marketplace) and `superpowers` from `claude-plugins-official`, which the mattstack skills and every team pack call. An existing install from `superpowers-marketplace` counts; rt does not add a second copy.

## Home repo backup

Your home repo (`~/.mattstack/user`) starts local-only. To back it up, point it at an empty repo you own, or let rt create a private one with `gh`:

```bash
rt home remote set https://github.com/you/mattstack-home.git
rt home remote set --create        # creates a private mattstack-home repo first
```

## Integration health

`rt setup status` warns when an integration token is approaching expiry, so you can rotate it before it breaks.

When you connect GitHub or GitLab, the Connect sheet links to the forge's new-token page with the scopes rt needs already checked and the token named `mattstack`:

| Forge | Joining a team | Owning a team |
|---|---|---|
| GitLab | `read_api`, `read_user` | `api` |
| GitHub (classic token) | `repo`, `read:org` | `repo`, `read:org` |

A token the forge accepts but that is missing a scope shows as invalid, naming the missing scope, and `rt setup <forge> connect` refuses it before storing it. The link targets GitLab 16 or newer; older self-hosted instances use a different token page.

## What Gets Installed

| Component | Description |
|---|---|
| `rt` binary | Shipped inside mattstack.app (`Contents/MacOS/rt`), linked onto your PATH |
| `mattstack.app` | Menu bar app... daemon health, notifications, auto-updates |
| `rt-context` extension | VS Code/Cursor... branch + ticket in status bar |
| Background daemon | Caches MR/branch data, scans ports, guards git hooks |
| Bundled helpers | `jq`, `gh`, `glab`, `bun`, `node`, `fast-browser` (pinned and shipped inside the app, not installed onto your system) |
| Shell alias | `rtcd`... fast worktree directory switching |

## PATH

`rt setup status` checks that `~/.local/bin` is on your PATH and that rt's own entry is present. Two distinct states:

- **missing**: `~/.local/bin` is not on PATH at all. Run setup to fix it.
- **unowned**: `~/.local/bin` is on PATH but rt didn't put it there (no owner attribution). This is informational, not a failure.

## Finishing setup

The setup wizard gates its Finish step on two things: a writing style, and the [Fast Browser](https://chrome.google.com/webstore/detail/fast-browser) extension.

### Writing style

Every review or reply an agent drafts is written in one writing style. The Done screen asks you to pick one of the mattstack plugin's presets or name your own skill, and this row cannot be skipped. From a terminal:

```bash
rt skills writing-style list                       # the three presets, then styles you can type
rt skills writing-style use <skill-id>             # choose one (omit the id to pick)
rt skills writing-style new my-voice --from sparse # start your own style from a preset
```

### Fast Browser

Without the extension, agents cannot capture screenshots or annotate evidence from your browser.

If Chrome is not installed, the gate is skipped automatically. Otherwise, the Done screen shows "One step left before you finish" with Finish disabled until the extension is detected.

You can skip the gate from the wizard ("Skip for now") or from the CLI:

```bash
rt setup waive tool.fast-browser-extension     # skip on this Mac
rt setup unwaive tool.fast-browser-extension   # re-arm later
```

In the app's Settings, the Fast Browser pane shows "Skipped on this Mac" with an **Un-skip** button when waived.

## Upgrade

```bash
rt update
```

[`rt update`](/reference/update) asks mattstack.app (Sparkle) to check for an update; the app owns the whole upgrade lifecycle (signature verification, staged install, restart); `rt` never downloads or installs its own updates. If the app isn't running, `rt update` points you at the latest release instead.
