# Onboard a repo

There's no explicit "add repo" step for everyday use. Any git repo is indexed the first time you run a repo-aware rt command inside it:

```bash
cd ~/code/my-repo
rt cd                # or rt run, rt code, anything repo-aware
```

On that first invocation rt will:

1. Derive a stable identity for the repo from `git config --get remote.origin.url`. A repo with no origin gets a path-based identity instead, so local commands still work.
2. Record it in the repo index inside `~/.mattstack/rt/state.db`.
3. Create a per-repo data directory under `~/.mattstack/rt/repos/`.

All of this lives under `~/.mattstack/`, never inside the repo itself. Onboarding never adds files, config, or commits to your project.

## Background tracking

Indexing a repo is not the same as tracking it. The daemon only refreshes data in the background for repos you have explicitly granted:

```bash
rt repos register . --track live    # index this repo and grant background tracking
rt daemon track                     # list tracking, or change a repo's level: live, poll, or off
rt repos prune                      # drop index rows whose repos no longer exist on disk
```

An untracked repo still works everywhere; its data is fetched on demand instead of kept warm. Once a repo is tracked, merge-request data refreshes every 5 minutes. See [Daemon](/guides/daemon) for what each tracking level does.

## Optional per-repo config

| Command | When you need it |
|---|---|
| [`rt repos register --track`](/reference/repos/register) | You want the daemon refreshing this repo in the background |
| [`rt hooks`](/reference/hooks) | The repo uses husky and you want a quick on/off toggle |

## Global settings that affect every repo

Set these once; they apply to all repos and are stored under `~/.mattstack/`, not in any repo. The setup window's checklist covers the tokens; from a terminal:

```bash
rt setup gitlab connect        # GitLab token, for MR data and notifications
rt setup linear connect        # Linear API key, for ticket lookup
rt settings linear team        # default Linear team
rt settings notifications      # pick which events fire native macOS notifications
rt settings extension          # install the rt-context status-bar extension into local editors
```

See [rt setup gitlab connect](/reference/setup/gitlab/connect), [rt setup linear connect](/reference/setup/linear/connect), [rt settings linear team](/reference/settings/linear/team), [rt settings notifications](/reference/settings/notifications), and [rt settings extension](/reference/settings/extension) for details.
