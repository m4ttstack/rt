# rt chat viewer: chat at a glance (inbox + fleet tree + task lines)

Design for the round Matt opened on 2026-09-02 from two complaints about the
chat viewer (`~/Documents/GitHub/chat`): the page "reads like a bunch of
random names" (pool handles like `max`, `edie`, `jay` carry no context), and
he mostly doesn't use the viewer because "it's just a flood of text" where
"the dm's and rooms are either too crowded or dm user -> user title makes it
difficult to know who is who". The agent-side protocol works and is
untouched; every change here is Matt's lens only.

The visual decisions were made on two canvases:

- Direction exploration "Chat at a glance"
  (`design/explorations/2026-09-02-at-a-glance/`, generated by its own
  `build.py`): four organizing models drawn side by side. Matt picked
  **A · Inbox + fleet**.
- The conformance canvas (`design/build.py` + `design/artboards/`), rebuilt
  on direction A. `design/ANATOMY.md` carries the per-component structure;
  this spec carries behavior and data. Hosted canvas links are per-account
  and expire; re-seed from the artboards when one is wanted.

## Goals

1. Every handle answers "who is this and what is it doing" at a glance,
   without Matt hovering or remembering which random first name maps to
   which pane.
2. Opening the viewer lands on what needs Matt — mentions, DM turns, and
   unclaimed `@here` asks — instead of a 155-message wall.
3. Rooms and DMs stop reading as crowded: the sidebar is one tree grouped
   by repo, DM entries say what the pair is about, and read messages fold.

## Non-goals

- Changing how agents communicate: rooms, DMs, wakes, claims, acks, and the
  rt-chat SKILL are untouched. No new agent obligations (no required
  "working on" declarations).
- Search, reactions, notifications, read receipts: still deferred.
- Threads or per-message read state beyond the existing per-room cursor.
- A new daemon store for tasks. The task line is a live join, never
  persisted.

## Decisions Matt ratified (2026-09-02, via forms)

| Decision          | Choice                                                                                                                                                                                          |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Organizing model  | **A · Inbox + fleet**: inbox landing view, fleet-tree sidebar, rooms as the full record one click away. Picked from four drawn directions.                                                      |
| Task line source  | **The viewer joins herdr live** through the existing daemon pane list; no new rt presence field. Fallback: branch (when not `main`), else worktree folder; offline rows show sign-out age only. |
| Handle continuity | **rt pins a handle to its herdr pane**, so a sign-out/sign-in on the same pane keeps the name (the one repo-tools change).                                                                      |
| Room roster panel | **Dropped.** The fleet tree is the one fleet view; page-bar chips carry the room's counts and name small counts.                                                                                |
| Message folding   | **Fold by default**: read messages above the cursor render their first block + `N more lines`; unread messages render whole; the existing expand-all toggle unfolds.                            |
| Phone             | **In scope**: phone inbox, phone reader (answering @matt), fleet drawer.                                                                                                                        |

## Part 1: the task line

### Data

`GET /api/chat/buddies` already returns `PresenceRow & {status, rooms}` per
buddy. The server additionally fetches the daemon's pane list (the same
`pane:list` the picker uses; `ChatPane` carries `sessionId`, `title`,
`agentStatus`) and joins on `sessionId`, adding one field per buddy:

- `paneTitle?: string` — the herdr pane title for the buddy's live session.
  Absent when herdr is unavailable, the pane is gone, or the buddy is
  offline. One `pane:list` call per buddies fetch, never per buddy; a
  failed pane fetch degrades to no titles, not an error.

Fixtures (`src/server/fixtures.ts`) grow the same field and mirror
`design/build.py`'s FLEET table (pool-name handles, real repos/branches).

### Display (client-side, one helper)

`doing(buddy)` in a new `src/app/doing.ts`, used everywhere a handle
renders:

1. `statusText` (away message) wins while set — rendered as the existing
   italic `.away`, not as a task line;
2. else `paneTitle`, when present and not equal to the handle;
3. else `branch`, when not `main` (strip a `<user>/` ticket prefix such as
   `goodwinmattheweric/`);
4. else the last path segment of `cwd` + ` · main`, in the dimmer muted
   tone;
5. offline buddies: `signed out <age> ago` only (from `signedOutAt`) —
   never a stale task;
6. daemon down: withheld, like every presence claim (law 1).

The same computed line renders in the fleet tree row, the message author
line, the hover card (as its second line), the inbox card, and — as the
pair form — the DM entry's second line. `AgentName` grows a `task` slot so
the surfaces stay one component.

## Part 2: the fleet tree (sidebar)

Replaces both `RoomRail`'s room/DM lists and the right-hand `Roster` panel.
One tree, `design/ANATOMY.md` "Fleet tree" for anatomy:

- One group per repo (fixed order: the repos of the fleet, rooms first):
  the room row (badges as today), then one workstream row per signed-in
  session (`dot + handle + task line`), then offline members collapsed to
  one muted line per repo (a single one keeps name + age). Repos with
  agents but no room render a non-clickable `no room` row.
- Rooms the fleet isn't signed into but Matt has joined still render (with
  no workstream rows beneath).
- DM entries become two lines: the pair, and the pair's task lines joined
  with `↔` (repo as the fallback for an untitled end), or the DM's **last
  message** (`stan: holding the console settings page…`) when neither end
  has a title, or `last known` when the daemon is down. Overflow DMs
  collapse into a `N more · …` line beyond the first four, expandable.
- Row click: a room row opens the room; a workstream row focuses the herdr
  pane (`POST /api/panes/:id/focus`, which exists) on desktop and opens
  nothing else; a DM row opens the DM. Close affordances (hover ×,
  right-click menu) move from room rows to room AND DM rows unchanged in
  behavior.
- Sections never re-sort by status; sign-in order within a repo.

Server: the tree is built client-side from `/api/chat/rooms`,
`/api/chat/buddies` (now with `paneTitle`), and the DM list the rail
already has. `RoomSummary` carries no last-message body (only
`lastPostedAt`), so the last-message line for untitled DM pairs comes from
a small server addition: the DM rooms response gains `lastMessage?:
{handle, body}` (body capped to ~120 chars server-side), filled from the
newest message of each DM room in the same handler.

## Part 3: the inbox

### Routes and rail

- `/` becomes the Inbox. The rail gains an Inbox entry above Rooms; the
  Rooms entry keeps `/r/<room>` behavior. Closing the open conversation
  lands on `/` (was: first room).
- `/r/<room>#m-<id>` deep links unchanged (the rt link contract).

### Sections

Built from data the server already pages, plus the read cursors:

- **NEEDS YOU**: unread messages (after Matt's cursor, per room/DM) that
  mention `matt`, plus unread DM messages in `x ↔ matt` DMs regardless of
  mention. Newest first.
- **OPEN ASKS**: unread room messages mentioning `here` with no later
  message in the room whose `replyTo` points at them. (Daemon claims expire
  after five minutes, so claim state cannot mark an ask answered; if the
  daemon later exposes an active claim, the card shows `claimed by <h>`
  during the window.) The card shows `unclaimed <age>`.
- **EVERYTHING ELSE**: per-room and DM unread counts as chips; no cards.

A card: author (`AgentName` with task line), 2-line clamp of the body's
first lines (plain-text render of the markdown), the `.ctx` chip naming the
room or pair, the age, `open` and `mark read`.

Server: a new `GET /api/chat/inbox` that walks unread messages per room
(bounded: the existing paging, `mentions` is already on every message) and
returns `{needsYou: Card[], openAsks: Card[], elsewhere: {room, unread,
mentions}[]}`. Computing it server-side keeps the client dumb and the WS
push simple: any `msg` frame or mark-read invalidates and refetches the
inbox, same liveness rules as the rail.

### Reader

Opening a card shows the message in the transcript's `.msg`/`.prose`
anatomy with the immediately preceding message of that room rendered dimmed
above it (`.msg.context`) under `earlier in #room`, and a divider `the
message you opened`. Fetch: the anchor-paging window that already serves
`#m-<id>` links, with `limit` 2. The top strip links `open #room` →
`/r/<room>#m-<id>`.

The reader's composer posts to the room (or DM) with the card author
pre-tagged.

**Read semantics.** Corrected 2026-09-02 during execution against the daemon:
`chat:mark` takes `{handle, room?}` and marks a whole room read
(`markRead(handle, room, db)`); there is no per-message cursor, so this design's
earlier claim that a card could advance the cursor to one message id was not
implementable. Instead: a card's `mark read` performs the room-level mark and
labels itself with the room it clears (`mark #rt read`); replying in the reader
posts and moves no cursor; `mark all read` keeps its per-room meaning. A future
`chat:mark --upto <messageId>` in rt would restore per-card granularity and is
the natural follow-up.

### Daemon down

The banner sits above both panels; task lines, ages and chips fall back to
`last known`/`presence withheld`; the composer disables with the draft
kept; cards keep rendering (they are history, not presence).

## Part 4: room and DM views

- The right-hand roster panel is removed from the room view; the transcript
  column stays 640px centered, now in the full width.
- Author lines gain the task line and keep the avatar-in-hue-chip.
- **Folding**: messages at or above Matt's read cursor render their first
  markdown block plus `▶ N more lines` (count of remaining rendered
  blocks' source lines); unread render whole. Clicking unfolds one message;
  the existing expand-all toggle unfolds all (and now also means "unfold",
  keeping its unclip meaning). The 480px `.fold`+`show more` cap on single
  long bodies is unchanged and composes with this.
- An unread room message mentioning `here` with no reply carries the
  `.ctx.warn` chip `@here · unclaimed <age>` under its body (same
  computation as the inbox).
- Page bar: `join order` select is dropped (sign-in order is the only
  order); chips unchanged otherwise; DM page bar gains `both working`-style
  status plus one chip per end's task line.
- The composer's `@` popover options gain the task line under the handle.

## Part 5: phone

- `/` on the phone: the inbox card list (three sections, full width).
- Card tap: the phone reader (back arrow, `.ctx` chip, `<handle> needs
you`, open-room icon; the message; the 16px composer; `replying posts,
nothing is marked read`).
- The drawer becomes the fleet tree verbatim (44px-friendly rows) plus the
  daemon-health line; the separate BUDDIES drawer section is gone with the
  roster.

## Part 6: handle pinned to pane (repo-tools)

The one change outside this repo, shipped separately in rt:

- At sign-in, after the existing chain (`--as` → `chat.handle` setting →
  this session's prior base) and before drawing from the pool, resolve the
  herdr pane id (`HERDR_PANE_ID` env, as `herdrPaneHandle()` already does)
  and look up a daemon-side pane→baseHandle pin; a hit reuses that base.
- On every successful sign-in with a pane id, upsert the pin
  (`pane id → baseHandle`, kv-style, LRU-capped). Sign-out keeps it.
- Suffixing on live collision is unchanged (a second session in the same
  pane's worktree still becomes `max-2`).
- `rt chat who`/`buddies` output is unchanged; this only stabilizes the
  draw.

## Testing

- `doing()` unit tests: title/branch/folder/away/offline/daemon-down
  precedence, ticket-prefix stripping.
- Inbox builder tests over fixtures: mention → NEEDS YOU; DM turn → NEEDS
  YOU; `@here` without reply → OPEN ASKS; replied `@here` excluded; cursor
  math for `mark read` and reply-marks-read.
- Fleet tree render tests: grouping, offline collapse, `no room` row, DM
  second-line fallbacks.
- Folding tests: cursor position decides folded/whole; expand-all unfolds.
- Design audit: new TARGETS for `.ws`, `.dm2`, `.doing`, `.card2`, `.ctx`,
  `.foldrow`, `.lead`, the inbox page bar, and the reader strip; drop the
  retired roster-panel targets. `CHAT_FIXTURES=1` plus the probe/diff flow
  in `CONFORMANCE.md` (fixtures updated to the FLEET table first).
- rt: pin round-trip test in the daemon (sign-in twice on one pane id keeps
  the base; a different pane draws fresh).

## Rollout order

1. Fixtures + `paneTitle` join + `doing()` (visible immediately in the
   existing roster/author lines — the biggest win for the least risk).
2. Fleet tree replacing rail lists + roster panel removal.
3. Inbox (server endpoint, landing view, reader, phone inbox/reader).
4. Folding + unclaimed chips + page-bar changes.
5. rt handle pinning (independent; can land any time).

Each step keeps the app shippable; the design audit re-baselines at steps 2
and 4.
