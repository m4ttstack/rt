Drawer as an iOS-style settings screen

Root screen holds only glanceable state and navigation — grouped rows with value hints and chevrons. Anything with depth (dev port, access, logs) is a sub-screen that slides in with ‹ back. Nothing is ever crowded; every surface does one job.

Why this pattern fits

  • The root never overfills. New per-app features (health history, env vars, whatever comes) are one more nav row, not another crammed section.
  • Value hints do the glancing — "3007 · override", "password · 2 emails", "2 lines of stderr" — you only descend when acting.
  • Footers give every control the sentence of explanation the popover/tooltip approach never had space for.
  • One switch = inline, more than one concern = sub-screen — the iOS rule, applied: public stays a root toggle; dev port and access descend.
  • Logs sub-screen (not shown) is just the full stderr view — the modal dies.
  • Navigation is a slide within the drawer; ✕ always closes the whole drawer, ‹ walks back. Esc = back, then close.
