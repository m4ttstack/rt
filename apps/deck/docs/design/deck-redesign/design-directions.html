Deck redesign — three directions from first principles

The jobs deck serves, in order of frequency: ① "is my fleet healthy?" (glance) · ② "flip this public/private" (one click) · ③ "why is X broken?" (drill in) · ④ port wrangling & wiring new apps (rare). My diagnosis of the current mess: every rare job's controls are crammed inline into the status table — hover reveals, chip popovers, glyph mysteries, tooltip clipping all descend from that one decision. All three directions keep the Tokyo look; they differ in where job ③/④ controls live.

A — Status table + detail drawer  (my recommendation)

The table becomes pure status plus the single high-frequency action (public switch). Clicking a row slides a drawer out on the right that owns everything else for that app: dev port, access, logs, restart/edit/remove — labeled sections with room to breathe, no popovers, no hover reveals, no icon guessing, nothing clipped by table overflow. The devport popover we just built dissolves into a proper "dev port" section.

B — Fleet cards

Drop the table. Each app is a card in a responsive grid: big health state, name, public toggle, and a compact detail area per card. Scales visually like a status wall / ops dashboard.

C — Refined inline table

Keep everything inline but systematize it: actions always visible in a fixed rail (no hover reveal), port override as an expanding sub-row (no popover), labeled access text instead of glyph pairs. Smallest change from today.
